# Plan 01 — Data model (every table, every column)

Conventions: `snake_case` in SQL, `camelCase` in TS (Drizzle maps). Every table has `id uuid pk
default gen_random_uuid()`, `created_at timestamptz not null default now()`, `updated_at timestamptz
not null default now()` (updated by a trigger written in migration 0001). **Money is `integer`
minor units (cents)** — never float — plus a `currency char(3)` where relevant. Soft delete only where
noted. Foreign keys always indexed. Each migration is one `.sql` file generated by `drizzle-kit
generate` and read by him before applying.

## Entity map

```
users 1──* sessions
users 1──* addresses
users 1──* carts (0..1 active)      carts 1──* cart_items ──1 product_variants
users 1──* orders                   orders 1──* order_items (snapshot of variant)
orders 1──1 payments                payments ←── webhook_events (audit)
categories 1──* products 1──* product_variants 1──1 inventory
products 1──* product_images
shipping_methods (standalone)       orders ──1 shipping_methods (snapshot fields on order)
```

## Seed data (phase 1, step 6)
- 5 top-level categories by pet: Dogs, Cats, Birds, Fish, Small Pets. Sub-categories per pet where
  it makes sense: Toys, Beds & Housing, Food & Treats, Bowls & Feeders, Walk & Travel (dogs/cats),
  Cages & Stands (birds), Tanks & Decor (fish).
- About 40 products total: e.g. 10 dog, 10 cat, 7 bird, 7 fish, 6 small-pet. Variant axes: colour ×
  size for toys/beds/collars (3 colours × 3 sizes = 9), flavour × pack size for treats and food
  (3 × 2), single variant for decor. Roughly 200 variants.
- Theme data: each top-level category carries `attributes.accentColor` and `attributes.icon`
  (used by the UI for the colourful per-pet look).
- Every product 1–3 images with alt text, width, height, and a line in `CREDITS.md`.
- Stock: random 0–120, a few deliberately at 0 (sold out UI) and a few under threshold (admin badge).
- 2 shipping methods: standard (base 490, per kg 100, free over 4900), express (base 990, per kg 200).
- 1 admin user and 2 customers with obviously fake emails (`admin@pawsome.test`), password printed by the seed script, hashed in DB.
- Seed is idempotent (`ON CONFLICT (slug) DO UPDATE`), lives in `apps/api/src/db/seed/`, run with `pnpm --filter api db:seed`.
