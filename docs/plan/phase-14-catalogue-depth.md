# Phase 14 — Catalogue depth

Goal: grow the shop from 40 to ~120 products with a sixth pet (Reptiles), house brands, curated and
seasonal collections, badges, unit pricing, health-need filters, colour swatches and trial sizes.
**This phase builds first: later phases depend on its schema.**

## Learn / explain
- Derived vs stored data: badges and unit price are computed from facts we already hold (dates, stock,
  weight), so they can never drift; only genuinely editorial flags are stored.
- Integer-cent unit-price maths and a stated rounding rule (no floats, ever).
- Faceted search over normalised relations (brands) vs jsonb attributes vs tag tables (health needs).
- Many-to-many with ordering (collections), and seed data as a typed, validated pipeline.
- Enforcing a business rule (one trial size per customer) in the service layer **and** the database.

## Step 14.2 — pure helpers: unit price, badges (shared)
- `packages/shared/src/unit-price.ts`: `unitPriceCents(priceCents, netAmount, netUnit)` returns integer
  cents **per kg or per L**. Net amounts are stored as integers in the base small unit (g or ml), so
  `unit = round_half_up(priceCents * 1000 / netAmount)`. Rule stated in a code comment and in the UI
  footnote ("€4.20/kg, rounded to the nearest cent"). Items with no net amount return `null`.
- `packages/shared/src/order-status.ts` (owner of the **paid-or-later** rule, reused by 17, 22 and the
  Bestseller badge below): `isPaidOrLater(status)` = every order status except `pending_payment` and
  `cancelled`, so statuses added by phases 22/23 count automatically; plus `ORDER_STATUS_LABELS`
  (customer-facing text per status; 22 and 23 add their entries, 20 tracking renders it).
- `packages/shared/src/badges.ts`: `deriveBadges(product, now)` → `New` (created < 30 days or
  `badge_new_until`), `Low stock` (any default-variant availability <= threshold, never raw numbers),
  `Sale` (any variant `compare_at_price_cents > price_cents`), `Eco` (`is_eco` manual flag),
  `Bestseller` (manual override OR top 10% by units sold in the last 90 days from `order_items` of
  paid-or-later orders; also the single source for the homepage bestsellers section in phase 20,
  recomputed on read with the 60 s cache, no job runner).
- Tests: table-driven unit tests incl. rounding edges (x.5 cents), zero/null weights, boundary dates.
- Commit: `feat(shared): add unit price and badge helpers`

## Step 14.3 — seed: Reptiles, brands, tags, collections
- Seed format: one typed file per area in `apps/api/src/db/seed/` (`brands.ts`, `tags.ts`,
  `collections.ts`, `products-<pet>.ts`) validated by a Zod `SeedProductSchema` at start-up, so a
  typo fails the seed, not the UI. Idempotent (`ON CONFLICT (slug) DO UPDATE`).
- Reptiles category + leaves: Terrariums, Heat & Lighting, Feeders & Bowls, Decor & Hides, Food.
- 4–5 fictional brands (e.g. Wagtail & Co, Whisker Works, Scaleby, Pebble & Pine, Tidepool): name,
  slug, tagline, story, accent colour. No real brand names (check each against a quick web search).
- Health-need tags: `joints`, `dental`, `calming`, `sensitive-tummy`, `skin-coat`, `weight`.
- Collections: Halloween, Christmas, Puppy Starter Kit, Eco Picks, Under €10 (manual); seasonal ones
  carry `starts_at`/`ends_at`.
- Tests: seed validation rejects a bad product; seed twice = same counts.
- Commit: `feat(api): add brands, tags, collections and reptile seed data`

## Step 14.4 — catalogue growth to ~120 products + image pipeline
- Write the remaining ~80 products so every leaf category has **>= 5 products** (a test counts per
  leaf and fails below 5). Mix of variant axes as phase 1; trial sizes on ~10 food/treat products
  (e.g. 50 g sample, one `is_trial` variant); 3-colour products carry `swatch_hex` per colour variant.
- Images: AI-generated by the **lead agent via browser automation** (not manual work by the owner);
  this pipeline is the single owner for every later phase's images (menu promos, hero slides, guide
  covers, gallery photos):
  1. a `docs/images-brief.csv` generated from the seed (slug, shot list, prompt, style suffix) so
     prompts stay consistent;
  2. the lead agent saves outputs to `apps/api/assets/raw/<slug>-<n>.png`;
  3. `pnpm images:process` (exists) resizes/compresses to `/products/` and writes width/height;
  4. every image gets a `CREDITS.md` row: "AI-generated (tool, date, prompt id), no third-party
     source, usable for the portfolio". Missing images fall back to a per-pet placeholder.
- Tests: seed test for >= 5 per leaf, unique SKUs, every image row has alt text and a file.
- Commit: `feat(api): grow seed catalogue to 120 products`

## Step 14.7 — trial sizes: one per customer
- Rule: a cart may hold quantity 1 of each trial variant; max **one trial unit per customer per
  variant**, ever. Check in cart add/update (409 `TRIAL_LIMIT`), re-checked in `POST /checkout`, and
  backed by a unique partial index on `trial_redemptions(customer_key, variant_id)` where
  `customer_key` is user id (guests: lowercase email at checkout). Rows written when the order is paid
  (works with the existing fake gateway; no Stripe needed). Rejected: cart-only check (bypassable).
- **Order events (owner: this phase).** Create `apps/api/src/modules/orders/events.ts`, a tiny typed
  in-process registry: `onOrderPaid`, `onOrderCancelled`, `onOrderRefunded({orderId, refundedCents,
  full})`; the order service emits, subscribers register at start-up. Trial redemptions subscribe now
  (write on paid, release on cancelled). Phases 18 (redemption release), 19 (points, referral, donation),
  22 (emits `refunded`) and 23 (store stock) subscribe instead of editing the order service each time.
  Rejected: a queue or DB triggers (more moving parts for a single-process demo).
- Tests: second add clamps, second order blocked, cancelled order releases the redemption.
- Commit: `feat(api): enforce one trial size per customer`
