## 4. Plan critique (phases 14–24)

1. **Size.** 14–24 add roughly 26–31 sessions on top of 0–13. Prioritise by portfolio value; trim
   phase 23 grooming (high complexity, low signal) and keep 24 small.
2. **Order events registry (14.7) needs written semantics.** In-transaction vs after-commit, what
   happens when a subscriber throws (must not roll back a payment confirmation), idempotency keys per
   subscriber, crash-loss after commit. Money-relevant subscribers (points, trial redemptions,
   store stock) should write in the same transaction or via an outbox like email. Add a spec + tests.
3. **No tax/VAT in the `priceCart` contract (18)** while the store is EU-facing and does Omnibus.
   Add an explicit decision: prices incl. VAT with a per-country rate and a VAT line on orders/emails,
   or state "tax 0, demo" everywhere.
4. **Phase 21 merged last touches every string.** De-risk: land 21.4's `t()` dictionary and
   locale-aware `formatMoney` early (start of wave 2), so phases 15–24 never add hard-coded strings.
5. **Move the job runner (19.1) earlier** — 18 (flash sales) and 19 both need it; one owner, built first.
6. **Phase 17 uploads on Render's ephemeral disk**: fine with seeded static photos, but say so on the
   PDP form in the demo, not only in the code comment.
7. **Phase 19 cron via GitHub Actions** is best-effort (delays of minutes to hours); jobs must stay
   idempotent and not time-critical (they are designed so: keep it that way).
8. **Phase 22 vet approval**: keep all copy fictional with a "demo, not medicine" banner; avoid any
   medical claims in a public repo.
9. **Merge the in-flight branches before starting new phases**: fix the failing test in 18, the 3 e2e
   failures, merge 14, rebase 20.
